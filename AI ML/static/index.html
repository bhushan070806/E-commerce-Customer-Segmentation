How to use this dashboard

  1. Dataset Analysis – review structure, dtypes and missing values of the loaded dataset.
  2. EDA – explore distributions, outliers, correlations and business patterns (all charts are computed live from the CSV).
  3. Run Training – executes K-Means + DBSCAN segmentation and 3 supervised churn classifiers on unseen test data (takes ~1-2 min on 50k rows).
  4. Evaluation / Comparison / Conclusion – inspect confusion matrices, overfitting analysis and the final model decision.
  5. Upload CSV – optionally replace the dataset with your own (same columns required) and re-run everything.

      Why these algorithms?

      • K-Means - the standard partitional clustering algorithm for Continuous RFM & behavioural data. Fast and scalable on 50,000 rows; k is chosen silhouettically (highest silhouette) instead of guessed.
      • DBSCAN - density-based clustering on a 2-component PCA projection. It does not need k and automatically flags sparse customers as noise, making it a useful outlier-lens on the segmentation.
      • Churn classification (Logistic Regression, Random Forest, Gradient Boosting) - turning the segmentation into an actionable prediction of the churn_risk_category. A linear baseline (LR) is compared against bagging (RF) and boosting (GB) ensembles, which model non-linear interactions and dominate on tabular data.

      Leakage prevention & train/test design

      • 70/30 train-test split applied separately for clustering and classification; the test set is never used for fitting.
      • Scalers, the median imputer, k and eps are all derived from the training fold only.
      • Columns derived directly from the target (churn_risk_score, churn_risk_category, RFM sub-scores, health/CLV proxies) are excluded from churn-training features to avoid label leakage.
      • Stratified split preserves the churn class balance; clustering metrics are reported on unseen test data.

            Limitations & future work

            • Churn categories are highly imbalanced (e.g. “Very High” is rare); macro-F1 is reported alongside accuracy so minority classes are not hidden.
            • DBSCAN’s single dominant density blob shows the data is strongly dense-central; DBSCAN acts mainly as an outlier detector here.
            • Future work: SHAP explainability, survival analysis for churn timing, cluster-specific uplift campaigns with A/B testing, deployment of the chosen model behind a REST scoring endpoint.
